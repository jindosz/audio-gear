# 청력 측정 EQ 검토 (2026-11-20, 아직 안 만듦)

사용자가 가져온 Gemini 명세서("Hearing Test & Personalized EQ")를 이 앱 구조(안드로이드 앱의 폰 전체 EQ, 127밴드 변환)에 맞춰 검토한 결과. 만들 때 이 문서로 설계를 시작한다. 이전 검토(2026-10-24)는 CLAUDE.md 로드맵 "청력 측정 EQ" 항목.

## 목표
- 웹 오디오 순음으로 좌·우 귀의 상대 역치(겨우 들리는 크기)를 재서 맞춤 보정 EQ를 만든다.
- 가장 쓸모 있는 경우: 좌·우 청력 차이, 나이에 따른 고음 저하. 정상 청력이면 효과가 작다(대부분 측정 오차 범위).
- 비교 대상: 삼성 "Adapt Sound". 이 앱만의 차별점은 헤드폰 측정치 반영, 헤드폰 EQ와 합치기, 결과 그래프, 좌·우 따로 보정.

## 명세서에서 그대로 가져갈 것
- 3가지 모드: 좌·우 균형(약 1~2분, `[500, 1000, 4000]`) → 1단계(`[125, 250, 500, 1000, 2000, 4000, 8000]`) → 2단계(정밀). 좌·우 균형부터 만든다.
- 순음: `OscillatorNode`(사인파) + `GainNode` + 좌·우 분리(`StereoPannerNode` ±1 또는 `ChannelMergerNode`), 0.4초 켜짐/0.4초 꺼짐 반복, 30ms 페이드, 아주 작게 시작하고 최대 크기 제한.
- 계단법(수정 Hughson-Westlake): 들리면 −10dB, 안 들림·시간 초과면 +5dB, 올라가는 단계에서 3번 중 2번 같은 값이면 역치. 소리 없는 가짜 문항을 섞어 "안 들리는데 누름"을 거름. 응답 대기 시간과 문항 간격은 무작위로.
- 보정 세기 슬라이더(기본 50% = 절반 보정), 기존 EQ 규칙(부스트 최대 +6dB, `autoPreamp`).
- 시험 중 폰 EQ(`SystemEq`) 자동 끄기 → 끝나면 원래 EQ 다시 걸기(지금 앱은 폰 전체에 EQ를 걸어 시험 소리에도 걸리므로 필수).
- 안내: "의료용 검사가 아님", 조용한 곳, 노이즈 캔슬링 켜기, 삼성 사운드 효과 끄기. 어느 주파수든 좌·우 차이가 15~20dB 이상이면 이비인후과 진료 권유.
- 데이터: `EqPreset`에 선택 필드 `filtersR?`(DB version 올리지 않음, 예전 백업 호환).

## 고쳐야 할 것
1. **기준 곡선**: 명세서의 "ISO 226 30~40 phon 빼기"는 틀림. 역치를 재므로 정상 귀의 **역치 곡선**(ISO 389-7 또는 ISO 226의 역치 곡선)을 뺀다. 안 빼면 정상 귀도 저음이 20dB 넘게 덜 들리는 것 때문에 저음을 크게 올리는 EQ가 나온다. 표준 수치는 구현 때 원문으로 확인(기억으로 넣지 않음).
2. **헤드폰 몫 빼기**: 측정 장비(GRAS·5128) 곡선에는 귓구멍 증폭(3kHz 근처 +10dB 이상)이 들어 있고, 표준 역치 곡선은 머리 앞 공간 기준이라 그대로 빼면 3kHz가 크게 틀어진다 → 헤드폰 곡선 그대로가 아니라 **중립 타깃(확산음장 등)에서 벗어난 만큼(편차)**만 뺀다. 고음(5kHz 위)은 장비와 실제 귀 차이가 커서 1/1옥타브 스무딩 또는 줄여서 반영.
3. **블루투스 이어폰**: 많은 무선 이어폰이 아주 작은 신호에서 출력을 끄거나(무음 처리) 자동으로 키운다 → 미디어 볼륨을 중간 이상(예: 60%)에 고정해 시험 신호가 너무 작아지지 않게 하고, 이어폰 앱의 적응형 EQ·주변 소리·자동 볼륨은 끄도록 안내, 가능하면 유선 권장.
4. **작업 순서**: 명세서는 좌·우 균형 화면(3단계)이 좌·우 따로 EQ(4단계)보다 먼저라 결과를 폰에 걸 수 없음. 좌·우 균형은 EQ가 아니라 **좌·우 음량 차이 하나**라서 DynamicsProcessing의 채널별 입력 음량으로 먼저 만든다.
5. **고음 범위 모순**: 2단계에서 10k·12kHz를 재지만 기존 EQ 규칙은 8kHz 위를 줄여 12kHz에서 0 → 청력 EQ만 고음 규칙을 따로 두거나, 10kHz까지만 잰다. 10~12kHz는 이어팁 착용에 따라 크게 흔들림.

## 명세서에 없던 설계 결정
6. **헤드폰 EQ와 합치기**: 폰에는 EQ가 하나만 걸린다. 청력 결과를 별도의 **"내 귀 보정" 층**으로 저장하고, 어떤 EQ를 걸든 그 위에 더한다. 이 앱은 EQ를 127밴드 값(`eqDevice.ts`)으로 바꿔 거는 구조라 층 더하기가 쉽다(명세서의 "eqPresets에 저장"보다 이 구조에 맞음).
7. **Wavelet은 좌·우 따로 EQ 불가**(GraphicEQ는 공통 하나). APO는 `Channel: L` / `Channel: R`로 가능. 내보내기 화면에 "Wavelet은 좌·우 평균"이라고 안내.
8. **결과의 기준 기기 저장**: 헤드폰 몫을 빼지 않은 결과는 그 헤드폰 전용 → 시험에 쓴 기기·측정치와 날짜를 함께 저장.

## 우선순위 낮춤
- 마이크로 주변 소음 재기: 폰 마이크는 실제 크기를 모르고 노이즈 캔슬링을 켜면 의미가 줄어드는데, 마이크 권한(`RECORD_AUDIO`)과 블루투스 통화 모드 전환 위험이 있음 → 처음엔 빼고 안내만. 넣는다면 마이크 트랙을 모두 멈춘 뒤 약 1초 기다렸다가 시험 시작.
- 볼륨 변화 감지: 웹 코드로는 폰 볼륨을 못 읽어 안드로이드 코드가 더 필요 → 처음엔 "시험 중 볼륨 버튼 누르지 않기" 안내.

## 제안 순서
1. 순수 계산 + vitest(`src/hearing.ts`): 계단법 규칙, 가짜 문항, 정상 역치 곡선 빼기, 헤드폰 편차 빼기, 절반 보정·제한
2. 좌·우 음량 차이 적용: `SystemEq`에 채널별 입력 음량, "내 귀 보정" 층 구조(`eqEngine.ts`에서 걸 때 더함)
3. 좌·우 균형 시험 화면(1~2분, `tonePlayer.ts` + 시험 팝업) → 결과를 바로 폰에 적용 = **첫 사용 가능 버전**
4. 좌·우 따로 EQ: `eqDevice.ts`가 채널별 127밴드, `SystemEqService`가 `setPreEqByChannelIndex`, APO `Channel` 내보내기, Wavelet 안내
5. 1단계·2단계 모드와 결과 그래프, 헤드폰 편차 빼기 켜고 끄기
