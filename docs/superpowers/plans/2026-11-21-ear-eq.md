# 내 귀 보정 EQ Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 양쪽 귀의 주파수별 역치를 계단법으로 재서, 정상보다 덜 들리는 만큼의 절반을 올리는 "내 귀 보정" 층을 만들고 안드로이드 앱에서 귀마다 따로 모든 EQ 위에 더한다.

**Architecture:** 계단법은 `src/hearingTest.ts`, 보정 계산은 `src/earEq.ts`(둘 다 순수 함수). 저장·적용은 `src/earEqStore.ts`가 `eqEngine.ts`에 층을 등록하고, `eqEngine`은 마지막으로 건 EQ를 기억해 층·균형이 바뀌면 다시 건다. `eqDevice.ts`가 채널별 127밴드를 만들고, 네이티브는 오른쪽 게인 배열을 받아 `setPreEqByChannelIndex`로 채널마다 건다.

**Tech Stack:** React 19 + TS, vitest, Web Audio API, Chart.js, Capacitor 8 자바(DynamicsProcessing)

**Spec:** `docs/superpowers/specs/2026-11-21-ear-eq-design.md`

## Global Constraints

- 주파수 순서 1000 → 2000 → 4000 → 8000 → 500 → 250 → 125, 끝에 1000 한 번 더. 왼쪽 귀 전부 → 오른쪽 귀 전부.
- 크기: 시작 −40dBFS, 최대 −10dBFS(그 이상 절대 안 냄), 최소 −100dBFS. 들림 −10dB, 안 들림 +5dB, 올라가는 단계에서 같은 크기 2번 들리면 역치, 한 주파수 최대 20번.
- 소리 0.25초 × 3번(간격 0.15초), 페이드 20ms, 앞 무음 0.3초. 응답 시간 2.5초, 소리 간격 1~2.5초 무작위, 가짜 문항 15%.
- 경고: 가짜 문항에서 누른 게 한 귀에 3번 넘음, 1kHz 두 값 차이 10dB 넘음.
- 보정: (상대 역치 − 정상 상대 역치 − 기기 몫) − 5dB, × 세기(기본 0.5), 0~+6dB. 깎지 않음. 상대 = 500·1k·2k 평균 기준. 기기 몫은 1옥타브 스무딩, 5kHz 위는 절반. 8kHz 위는 12kHz에서 0으로 줄임, 125Hz 아래는 125Hz 값.
- 정상 역치(ISO 226:2003 Tf, 공개 구현 3곳에서 같은 값 확인: Rsantct/audiotools `iso226.py`, jcarrano/rtfi `scripts/iso226.py`, porres/pd-psycho `Classes/iso226.c`): 125 → 22.1, 250 → 11.4, 500 → 4.4, 1000 → 2.4, 2000 → −1.3, 4000 → −5.4, 8000 → 12.6 dB.
- 기기 고르기 칸 아래 늘 보이는 경고 "측정치는 측정자마다 기준이 달라 원음을 해칠 수 있어요", "모름"이면 기기 몫 빼지 않음, 결과에 뺀 측정치 출처 표시.
- localStorage `ear.profile`, 백업 제외. 균형만/보정만 상태 이름은 "내 귀 보정"(1단계 `EAR_BALANCE_NAME`을 이 이름으로 바꿈).
- 화면 문구 "~했어요"체, 설명은 `Help`, 토글 `ToggleButton`, 선택 상자 `Select`, 손가락 화면 44px 이상, 답변·주석 한국어, 커밋에 모델 이름 금지.

## Review Focus

1. 시험 중 뒤로 가기·닫기 → 소리 멈춤, bypass 풀림, 진행 버림(Task 4: `finally`에서 정리, 1단계 `EarBalanceDialog`와 같은 방식).
2. 최대 크기(−10dBFS)에서도 안 들리는 주파수 → 무한 반복 없이 "못 잼(최대에서도 안 들림)"으로 끝나고, 보정은 그 주파수를 +6dB 상한으로만(Task 1 테스트 `atLimit`, Task 2 테스트).
3. 보정이 켜진 상태에서 EQ를 바꿔 걸거나 끄기 → 층이 늘 함께 걸림, 끄면 "내 귀 보정"만 남음(Task 3, `reapply` 경로).
4. 정상 귀(상대 역치가 ISO와 같음) → 보정 0(Task 2 테스트 `normal ear → all zero`).
5. 예전에 저장된 `eq.applied`(eq 필드 없음) → 다시 걸기가 실패하지 않고 건너뜀(Task 3).

### Task 1: 계단법 `src/hearingTest.ts`

**Files:** Create `src/hearingTest.ts`, `src/hearingTest.test.ts`

**Interfaces — Produces:**
- `HEARING_FREQS = [1000, 2000, 4000, 8000, 500, 250, 125] as const`, `RECHECK_FREQ = 1000`
- `START_DB = -40`, `MAX_DB = -10`, `MIN_DB = -100`
- `interface Staircase { level: number; trials: { level: number; heard: boolean; ascending: boolean }[]; threshold: number | null; atLimit: boolean }`
- `newStaircase(): Staircase`
- `respond(s: Staircase, heard: boolean): Staircase` — 새 객체. 다음 level, 끝나면 threshold
- `isCatchTrial(rand: () => number): boolean`(rand() < 0.15), `gapMs(rand: () => number): number`(1000~2500)
- `interface EarResult { freqs: number[]; thresholds: (number | null)[]; atLimit: boolean[]; recheck: number | null; falseAlarms: number }` (freqs는 오름차순으로 정리해 저장)
- `earWarnings(r: EarResult, firstAt1k: number | null): { falseAlarms: boolean; unstable: boolean }`

- [ ] **Step 1: 테스트** — 처음 level −40; 들림 → −50; 안 들림 → +5; "들림, 안 들림, 들림(올라가는 단계), 안 들림, 들림(같은 크기 두 번째)" → threshold = 그 크기; 계속 안 들려 −10에 닿고 두 번 더 안 들리면 threshold −10·atLimit true; 계속 들려도 −100 아래로 안 내려감; 20번째 응답 뒤 threshold가 정해짐(null 아님); `isCatchTrial(() => 0.1)` true·`(() => 0.2)` false; `gapMs` 범위; `earWarnings` falseAlarms 4 → true, 1k 0 vs −11 → unstable

### Task 2: 보정 계산 `src/earEq.ts`

**Files:** Create `src/earEq.ts`, `src/earEq.test.ts`

**Interfaces:**
- Consumes: Task 1 `EarResult`; `similarity.prepare`, `SUMMARY_GRID`; `DEVICE_EQ_FREQS`
- Produces:
  - `ISO226_TF: Record<number, number>`(위 7개 값, 출처 주석)
  - `relativeLoss(freqs: number[], thresholds: (number | null)[]): (number | null)[]`
  - `deviceOffset(device: Values, target: Values, grid: number[], freqs: number[]): number[]` — 1옥타브 스무딩 값끼리 차이, 500·1k·2k 평균 기준, 5kHz 위 절반
  - `boosts(loss: (number | null)[], offset: number[] | null, strength: number, atLimit: boolean[]): number[]` — null은 0, 5dB 빼고 × strength, 0~6
  - `layerCurve(freqs: number[], boosts: number[], out: readonly number[]): number[]`
  - `interface EarProfile { measuredAt: string; device: { label: string; measurementId?: string; source?: string } | null; left: EarResult; right: EarResult; strength: number; on: boolean }`
  - `EarLayer = { left: number[]; right: number[] }`(DEVICE_EQ_FREQS 127개)

- [ ] **Step 1: 테스트** — 정상 귀(역치 = ISO 값 + 상수) → 모든 boosts 0; 4kHz만 15dB 더 나쁨, strength 0.5 → 4kHz 5dB; 30dB 나쁨 → 6으로 자름; 더 잘 들림 → 0; null → 0; atLimit → 6 상한; `layerCurve`는 125Hz 아래 125 값, 8k→12k 사이 줄고 12k 이상 0, 2k~4k 사이는 두 값 사이; `deviceOffset`이 기기 = 타깃이면 0
