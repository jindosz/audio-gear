# 계정과 PC↔폰 동기화 설계 (2026-11-21)

## 목적
- 사용자가 원한 것: 계정을 만들어 **PC와 폰(웹·안드로이드 앱)의 데이터를 자동으로 맞추기**. 나중에 **공유**(예: EQ 공개)까지 생각하고 있음.
- 무료로. 개인·지인 규모(하루 활동 수백 명 이하)를 우선.

## 목표 / 하지 않을 것
- 목표(이번 범위): 이메일 계정(가입·로그인·로그아웃·비밀번호 찾기·계정 삭제), 항목별 동기화(수동 → 자동), 다른 기기에서 처음 로그인하면 내 데이터가 내려옴.
- 하지 않음(이번엔): 공유, 구글 로그인(안드로이드 앱 안 웹 화면에서는 별도 플러그인 필요), 실시간 반영(다른 기기 화면이 즉시 바뀌기 — 읽기 횟수를 많이 씀), 필드 단위 병합.
- 실패로 볼 것: 인터넷이 없거나 로그인 안 하면 앱이 안 됨(로컬이 기본이어야 함), 지운 항목이 다른 기기에서 되살아남, 남의 데이터가 보임, EQ 슬라이더를 끌 때마다 서버에 써서 무료 한도가 금방 참.

## 방식 결정
- 사용자 선택: **Firebase**(Auth + Firestore), **A. 항목별 동기화**.
- 고르지 않은 것: B. 백업 파일 통째로 동기화(무겁고 지운 항목이 살아나며 공유로 못 넓힘), Supabase(무료 프로젝트가 1주일 안 쓰면 멈춤), Cloudflare Workers + D1(로그인·API를 직접 만들어야 해 보안 위험이 큼).
- 사용자 요청: **나중에 Cloudflare로 옮길 수 있게** 서버와 이야기하는 코드를 한 곳(`src/syncBackend.ts`의 인터페이스 + `src/firebaseBackend.ts` 구현)에 모은다. 동기화 규칙(`src/sync.ts`)은 서버 종류를 모르는 순수 함수.

## 무엇을 동기화하나 (내 판단으로 정한 것)
- 올림: 기기(`devices`, 보유·찜·메모·특징 포함, 목록에서 눌러 저장된 기기도), 측정치(`measurements`, **곡선 포함** — 목록에서 받은 측정치는 어디서 받았는지 경로가 저장돼 있지 않아 다시 받기가 불확실하고, 내 계정 안의 개인 사본이라 재배포가 아님. 곡선 하나 약 10KB로 1GB에 수만 개), 커스텀 타깃(`targets`의 `isCustom`), 비교 탭(`tabs`), EQ(`eqPresets`).
- 고를 때만: 내 귀 설정(균형·보정). 설정의 "내 귀 설정 동기화" 켜기/끄기, **기본 꺼짐**(건강 정보에 가까움, 백업과 같은 방식).
- 안 올림: AutoEQ·squig.link 목록(meta), 요약값(summaries), 기본 타깃, 화면 설정(localStorage: 목록 폭·테마 등).

## 데이터 변경
- 동기화하는 모든 레코드에 `updatedAt`(ms)을 둔다(없는 예전 데이터는 `createdAt` 또는 0으로 봄). 쓰는 곳(`repo.ts`)에서 고칠 때마다 갱신.
- 지우기 표시: 새 테이블 `deletions: '[table+id]'`(Dexie version 5, `{ table, id, deletedAt }`). `repo.ts`의 지우기 함수가 지울 때 여기 기록(로그인 안 했어도 기록, 동기화 뒤 서버에 올리고 30일 지나면 정리).
- 동기화 상태: localStorage `sync.state` = `{ lastPulledAt, lastPushedAt }`(계정별).

## 서버 구조 (Firestore)
- `users/{uid}/{table}/{id}` 문서 = 레코드 + `updatedAt` + `deleted?: true`.
- 보안 규칙: `users/{uid}/{document=**}`는 `request.auth.uid == uid`일 때만 읽기·쓰기. 문서 크기 1MB 제한 안(측정치 하나 수십 KB).
- 지역: 서울(`asia-northeast3`).
- 앱 설정값(apiKey 등)은 `src/firebaseConfig.ts`에 커밋(공개돼도 되는 값, 막는 건 보안 규칙).

## 동기화 규칙 (순수 함수 `src/sync.ts`)
- 내려받기: 서버에서 `updatedAt > lastPulledAt`인 문서만 질의(바뀐 것만 읽음).
- 합치기: 같은 id면 `updatedAt`이 큰 쪽이 이김(같으면 서버). 서버 문서가 `deleted`면 로컬에서 지움(지우기 표시는 남기지 않음). 로컬 지우기 표시가 서버 문서보다 늦으면 서버에 `deleted`로 덮어씀.
- 올리기: 로컬에서 `updatedAt > lastPushedAt`인 레코드와 지우기 표시를 묶음(batch, 한 번에 최대 500개)으로.
- 순서: 내려받기 → 합치기 → 올리기. 시계가 기기마다 조금 달라도 "나중에 고친 쪽이 이김"이 대체로 맞음(오차는 받아들임).
- 처음 로그인(그 기기에서 처음): 서버 전체를 내려받아 로컬과 합침(로컬에만 있는 것은 올림). 다른 계정으로 로그인하면 묻기: "이 기기의 데이터를 이 계정에 합칠까요?"

## 언제 맞추나
- 2단계(수동): 설정의 [지금 동기화].
- 3단계(자동): 로그인 상태에서 앱을 열 때, 앞으로 다시 가져올 때, 인터넷이 다시 연결될 때, 고친 게 있으면 **마지막으로 고친 뒤 30초**(EQ 슬라이더처럼 자주 바뀌는 것을 모아서), 화면을 떠날 때(`visibilitychange` hidden). 같은 때 한 번만 돌게.
- 무료 한도(대략 하루 읽기 5만·쓰기 2만, 저장 1GB — 만들 때 공식 문서로 확인): 한 사람 하루 50~100번으로 하루 활동 500~1,000명. 한도를 넘으면 그날은 동기화만 실패하고 앱은 그대로(토스트 한 번).

## 화면
- 설정 맨 위 "계정" 묶음: 로그인 전 [로그인 / 가입](팝업: 이메일·비밀번호, [로그인]·[가입]·"비밀번호를 잊었어요"), 로그인 후 이메일 · "마지막 동기화 3분 전" · [지금 동기화] · [로그아웃] · 고급 안에 [계정 삭제](서버의 내 데이터와 계정 지움, `askConfirm` danger, 이 기기 데이터는 남김).
- 동기화 중·실패는 토스트. 로그아웃해도 이 기기 데이터는 그대로.
- 웹과 안드로이드 앱 모두(이메일 로그인은 앱 안 웹 화면에서도 됨).

## 사용자가 해 줄 일
- Firebase 콘솔에서 프로젝트 만들기(무료 Spark, 결제 수단 등록 안 함 → 요금 걱정 없음), Authentication에서 이메일/비밀번호 켜기, Firestore 만들기(서울), 보안 규칙 붙여 넣기, 웹 앱 등록 후 설정값 알려 주기. 순서는 `docs/firebase-setup.md`로 안내.
- 작업 환경에서 Firebase 주소로 나가는 게 막혀 있으면 실제 연결 시험은 사용자 PC·폰에서.

## 작업 순서(제안)
1. 데이터 변경: `updatedAt` 갱신·지우기 표시(`deletions`, DB version 5) + 순수 합치기 규칙 `sync.ts` + 테스트 (서버 없이 끝남)
2. 서버 창구: `syncBackend.ts` 인터페이스, `firebaseBackend.ts`, 설정값, 보안 규칙 파일(`firestore.rules`), 사용자 안내 문서
3. 계정 화면과 [지금 동기화]
4. 자동 동기화, 내 귀 설정 동기화 켜기/끄기, 계정 삭제

## 남겨 둔 것(만들면서 정함)
- Firebase SDK는 로그인한 사람만 받게 따로 불러오기(`import()`)로 처음 화면 크기를 늘리지 않음.
- 비교 탭의 선택(색 순번)이 기기마다 달라 자주 충돌하면 탭은 동기화에서 뺄지 써 보고 정함.
